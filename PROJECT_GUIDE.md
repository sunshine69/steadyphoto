## 🏗️ Architecture Overview

### Backend (Go)
- **Framework**: Standard `net/http` (no external web framework)
- **Database**: PostgreSQL via `sqlx` + `lib/pq`
- **Port**: 8081 (configurable via `API_PORT` env)
- **Serves**: REST API + static Angular files (from `./angular-app/dist/steadyphoto-angular`)
- **File storage**: Local filesystem (`STORAGE_ROOT`, default `./storage`)
- **Thumbnails**: Generated by the worker (`THUMBNAIL_ROOT`, default `./storage/.thumbnails`)
- **TLS**: Optional HTTPS via `-tls-cert`/`-tls-key` CLI flags or `TLS_CERT`/`TLS_KEY` env vars
- **Cron worker**: Runs EXIF metadata extraction on a schedule (default every hour)
- **Session auth**: Cookie-based with `access_token` and `refresh_token`
- **Session cleanup**: Background goroutine runs every 30 minutes via `cron.AddFunc`

### Frontend (Angular 22)
- **Framework**: Angular 22.0.7 with standalone components (no NgModules)
- **Styling**: Bootstrap 5.3.8 + custom CSS (Tailwind installed but NOT used — all custom styles)
- **State management**: Services with RxJS (`Subject`, `BehaviorSubject`, `combineLatest`)
- **Build**: `ng build --base-href / --deploy-url /`
- **Route strategy**: Hash-based routing (`useHash: true`) — important for SPA routing behind nginx
- **Change detection**: All components use `ChangeDetectionStrategy.Eager` (the default)

### Deployment
- **Container**: Single Docker container (Go binary + built Angular)
- **Reverse proxy**: nginx recommended for TLS termination
- **Docker image**: `registry.cn-shanghai.aliyuncs.com/steadyphoto/steadyphoto:1.2.2`
- **Volume mounts**: `/data/storage` (media files) and `/data/postgres` (database)
- **nginx config**: `/etc/nginx/conf.d/default.conf` (in `nginx.conf` file in repo root)

## 🔐 Authentication Flow

1. **Registration**: `POST /api/register` → returns JWT as cookie (`access_token`)
2. **Login**: `POST /api/login` → validates credentials, returns JWT cookies
3. **Session validation**: `authMiddleware` checks cookie, falls back to DB session
4. **Logout**: `POST /api/logout` → clears cookies, deletes session from DB
5. **Role check**: Admin endpoints require `role == "admin"`
6. **Session cleanup**: Runs every 30 minutes via cron goroutine

### Auth Middleware
The `authMiddleware` checks:
1. `access_token` cookie (JWT)
2. If no cookie, falls back to `getUserFromSession()` (legacy DB sessions)
3. Sets `userID`, `userRole`, `isAuthenticated` headers on response
4. Returns 401 if no valid session found

### CORS
- Allows all origins (`*`)
- Allows `Authorization` header
- Allows GET, POST, PUT, DELETE, OPTIONS methods
- Preflight cache: 86400 seconds

## 🗄️ Database

PostgreSQL via `sqlx` with these repositories:
- `PostgresMediaRepository` — media items (photos/videos)
- `PostgresAlbumRepository` — albums and album-media relationships
- `PostgresUserRepository` — users and roles
- `PostgresSessionRepository` — auth sessions
- `PostgresShareRepository` — shared albums and memberships
- `PostgresMediaShareRepository` — media shares
- `PostgresAlbumShareRepository` — album shares
- `PostgresPublicShareRepository` — public share links
- `PostgresPublicShareAccessRepository` — access logs for public shares
- `PostgresJobRepository` — background job processing

## ⚠️ Known Issues & Mobile Limitations

### Critical Mobile Issues
1. **Sidebar is fixed 260px on ALL screens** — no hamburger menu, no responsive collapse
2. **Main content has `margin-left: 260px`** — takes up the full sidebar width even on mobile
3. **Header bar is complex** with date range inputs that won't fit on narrow screens
4. **No `@media` queries** for sidebar in `sidebar.component.ts` styles
5. **No mobile navigation pattern** — the entire app is desktop-first

### Incomplete Features (Placeholder Components)
- `/explore` — ExploreComponent shows "coming soon..."
- `/locked` — LockedFolder shows "coming soon..."
- `/screenshots` — ScreenshotsComponent shows "coming soon..."
- `/camera` — CameraComponent does NOT exist (route defined but no component)
- `/utilities` — UtilitiesComponent exists but is empty
- `/upload` — UploadComponent exists but is empty
- `/trash` — TrashComponent is NOT implemented
- `/map` — MapComponent exists but is a stub (no template/styles)

### Other Issues
- Photo grid uses `minmax(180px, 1fr)` which is too wide for phones
- Upload modal has a media query for `max-width: 480px` but sidebar doesn't
- Selection checkboxes are `position: absolute` and may overflow on small cards
- No touch-friendly sizes for buttons on mobile

## 💡 Tips for AI Assistants

1. **Angular uses standalone components** — no NgModules. Imports are declared in the `@Component` decorator.
2. **Services use `inject()`** — dependency injection via the inject function, not constructor parameters.
3. **RxJS is heavily used** — especially `Subject`, `BehaviorSubject`, `combineLatest`, `switchMap`, `debounceTime`, `distinctUntilChanged`, `filter`, `map`, `tap`.
4. **The `app.component.ts` is the main shell** — it contains the sidebar, header, and all modals/dialogs. Routes render into `<router-outlet>`.
5. **The sidebar is in `app.component.ts` template** — NOT in its own routed component. It's always visible.
6. **Go handlers are in `api/handlers.go`** — all HTTP handlers. Router is in `api/router.go`.
7. **Models are in `internal/models/`** — shared between API and database layers.
8. **Auth middleware is critical** — `authMiddleware` in handlers.go. All protected routes go through it.
9. **The server serves both API and static files** — no separate nginx needed in development, only in production for TLS termination.
10. **Thumbnail generation**: The `worker` processes EXIF data and generates thumbnails. The server has `ImageProxy` for on-demand thumbnail generation.
11. **When adding new features**, check if the route already exists in `app.routes.ts` and if a component exists in `components/`.
12. **The Angular `dist` path** served by Go is `./angular-app/dist/steadyphoto-angular` — make sure to rebuild Angular after changes.
13. **For API changes**, update the corresponding Go handler in `handlers.go` and the Angular service in `services/`.
14. **`ChangeDetectionStrategy.Eager`** is used everywhere — this is the default and means Angular checks for changes every tick. No need to switch to `OnPush`.
15. **The `selection.service.ts` and `share-trigger.service.ts` etc.** use a trigger pattern — a service broadcasts open/close events, and components listen to them.
16. **Environment configs**: `environments/environment.ts` (dev) and `environments/environment.prod.ts` (prod).
17. **When debugging**, check `angular-app/dist/steadyphoto-angular` after `npm run build`.
18. **The upload service** (`upload.service.ts`) handles multipart uploads with progress tracking via `HttpEventType`.
19. **For database changes**, update the repository in `internal/database/` and the model in `internal/models/`.
20. **The `make build-all`** command builds both Angular and Go — use this before deploying.
